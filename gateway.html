Arete Gateway

Join a governed realm with four HTTP calls.

The Arete Gateway is a small local service that lets any application participate in CNS/CP realms without embedding the SDK. Your app speaks plain REST to localhost; realm-side, the gateway is a full CNS/CP participant. Declare what you provide or consume — connections appear, events arrive, properties flow.

Why a gateway

Most systems that should participate in a realm — building management software, legacy services, scripts, constrained devices — will never embed a Node, Python, or Rust SDK. Almost everything can make an HTTP call.

The gateway carries the architecture's asymmetry into its API: declarations are writable; connections are read-only. Your application performs Declare — the substrate performs Reconcile, Match, and Bind. Connections appear to your app; they are never created by it. If you find yourself wanting POST /connections, that is the address-centric habit the architecture replaces.

It also encodes the field truths of building on CNS/CP so your app inherits them for free: declarations are validated against the CP registry before they are accepted, replay after restart is value-safe, registration is serialized, and reconnection is handled with clean single-use realm sessions. The ARETE.md gotcha list is, in effect, implemented behind an API.

1 · Declare

PUT a node, a context, and a capability declaration — provider or consumer of a registered Connection Profile.

2 · Bound

The orchestrator matches and binds. The connection materializes as a read-only resource with live properties.

3 · React

Events stream over SSE or signed webhooks: connection.created, property.changed — with origin, previous value, and ordering.

4 · Write

PUT property values back — broadcast at capability level, or addressed into one specific connection.

The four-call walkthrough

A light that participates meaningfully in a realm, end to end. Governed, per-event, auditable — and not a line of SDK in the app.

# 1 — a node for the app
PUT /v0/realms/myrealm/nodes/lobby-light            { "name": "Lobby Light" }

# 2 — the context it participates in
PUT .../nodes/lobby-light/contexts/lobby            { "name": "Lobby" }

# 3 — what it consumes (validated against the CP registry)
PUT .../contexts/lobby/declarations/consumer/padi.light
                                                    { "properties": { "cState": "0" } }

# 4 — where to hear about it
GET /v0/events?stream=sse                           # or register a signed webhook

When the substrate binds a switch, a connection.created event arrives; property.changed events carry sOut; the app answers with PUT …/properties/cState. To leave, DELETE the declaration — the substrate severs, connections are no more deleted by the app than they were created by it.

What ships in v0.1

🖥️

Built-in console

A live view at localhost:8420/ui — realm connectivity, your declaration tree with live properties, connections as they materialize, and the event tail. Own-side properties editable inline through the same governed endpoints as any app.

🔔

Events, two ways

Server-Sent Events with resume, and webhook delivery — HMAC-SHA256 signed, strictly ordered per hook, retried at-least-once for 24 hours. Same envelopes, same filters.

🔑

Capability tokens

Mint a narrow credential for a constrained device: one connection, named properties, read or write, revoked automatically when the binding is severed. The device uses the same property endpoints as an app — only the credential differs.

🌐

Multi-realm

One gateway holds sessions to several realms at once; everything the API does is scoped by a realm handle. Per-realm credentials stay in gateway config — apps never see them.

🔄

Idempotent by construction

Writes are PUT with client-chosen IDs. Retries are safe, redeclaration is a no-op, conflicts are explicit 409s. Declarations persist and replay across gateway restarts and realm reconnects — value-safe.

🛡️

Honest scope

v0.1 is deliberately localhost: one local API token, bound to 127.0.0.1. LAN and hosted placement are documented as unsupported until per-app tokens land. The limits are written down, not discovered.

Get it

Distributed on GitHub — clone or grab the release tarball. Node 18+ is the only prerequisite; there is no build step.

git clone https://github.com/project-arete/arete-gateway.git
cd arete-gateway
npm install                          # applies the SDK patch set automatically
cp config.example.json config.json   # point it at your realm
npm start                            # API on localhost:8420, console at /ui

Need a realm to point it at? Arete Hosting gives you one in a few clicks. The repository's INSTALL.md walks through setup step by step, and the README documents the full API surface, the event contract, and the design decisions.

Building with an AI assistant? The gateway pairs naturally with ARETE.md — point your assistant at the briefing file, tell it your app should talk to the local gateway, and describe what you want to build.
