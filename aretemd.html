ARETE.md

Build Arete applications with your AI assistant.

One file that teaches any AI coding assistant how to build applications on CNS/CP. Point your assistant at it, describe what you want to build, and it writes code that respects the architecture instead of guessing at it.

The file lives at one permanent address

https://raw.githubusercontent.com/project-arete/sdk/main/ARETE.md

Always serves the current version — nothing to pin, nothing to re-download.

Read ARETE.md View raw file

How to use it

Three steps, whichever assistant you prefer — Claude, ChatGPT, Copilot, Cursor, or an agent running in your terminal.

1 · Hand it over

Paste the URL into your assistant and ask it to read the file. Or save it as ARETE.md in your project root, where coding agents pick it up on their own.

2 · Describe the app

Say what you want in plain language — “a Python service that consumes padi.light and logs every state change”. The file supplies the architecture; you supply the intent.

3 · Point it at a realm

Run the result against your own orchestrator on Arete Hosting, then watch the connections bind in Arete Monitor.

Why a file like this is needed

AI models are fluent in REST, MQTT, and message brokers — and they will apply those instincts to Arete unless told otherwise. The code that comes back compiles and reads plausibly, but it is wrong in ways that are hard to spot: it connects by address instead of by declared capability, invents Connection Profiles that were never registered, or re-declares capabilities on every reconnect and silently wipes live values off the realm.

ARETE.md front-loads the distinctions that matter. It states the mental model in the vocabulary the architecture actually uses, makes the non-negotiables explicit, and carries a list of field-verified SDK gotchas that would otherwise cost an afternoon each to rediscover.

What’s inside

The mental model

Declare, broker, bind, operate — and the precise vocabulary that goes with it, including in-band versus out-of-band data flow.

The non-negotiables

Never connect by address. Every capability is a Connection Profile. Deny-by-default. Context is first-class.

The registry rule

How to resolve a profile from cp.padi.io before writing a line of code, and how to read its property flags correctly.

SDK quickstart

The identity chain — system, node, context, capability — with working Node and Python starting points.

Known gotchas

Eight traps verified in the field, each with the workaround, so generated code sidesteps them from the start.

A design checklist

The questions to settle before writing handlers when you introduce a new capability of your own.

A living document. ARETE.md is maintained in the Arete SDK repository and updated as the SDK evolves. Because the address above always resolves to the latest version, an assistant that fetches it is reading current guidance — and there is no version to keep track of on your end.
